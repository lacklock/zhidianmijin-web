# 职点迷津：首页与岗位页现有功能说明

> 调研日期：2026-09-13。本文用于后续页面重新设计，先记录现有功能与交互，不规定新版的视觉风格、布局或组件形式。
>
> 首版目标：制作首页和 `/jobs` 两个页面的可交互演示。使用模拟数据即可，其他页面可以占位，部分次要入口可以不响应；不要求开发真实业务系统。

## 1. 调研范围与结论

### 1.1 来源与验证范围

- [现有首页](https://www.zhidianmijin.com.cn/)：查看完整页面，操作主要筛选器、热门条件、导航菜单、主题菜单、推荐岗位依据切换，并从首页提交筛选进入岗位页。
- [现有岗位页](https://www.zhidianmijin.com.cn/jobs)：查看默认列表、带条件列表、更多筛选、排序、分页入口、每页条数菜单、零结果与近似结果状态。
- 抽样打开一条站内岗位详情，仅用于确认列表入口及返回关系，不将详情页纳入首版完整重写范围。
- 调研环境为桌面浏览器、未登录状态。未登录后的完整能力、移动端专用交互、后台匹配算法、外部招聘网站的投递流程均未验证。

下文将“页面展示的功能”“实测交互”和“未验证能力”分开说明。岗位数量、日期、企业与岗位名称均为调研时样本，不是新版必须固定使用的数据。

### 1.2 产品定位与核心路径

站内品牌名称为“职点迷津”，定位是以央国企机会为重点的求职筛选与决策工具。实际岗位库也包含民企、外资等单位，不应理解为仅展示央国企。

核心路径：

1. 在首页了解平台、选择求职条件或进入某个招聘方向。
2. 在岗位页查看匹配结果，继续缩小范围、排序和浏览。
3. 根据岗位条件与截止日期判断是否值得进一步了解。
4. 打开站内岗位详情或原始公告，核对实际要求与招聘状态。

首页还承担招聘公告发现、临近截止机会提示及推荐岗位解释功能。现有两页的主流程不直接完成简历投递。

## 2. 两页共有的功能

### 2.1 全局导航

| 入口 | 现有行为或去向 |
| --- | --- |
| 品牌标识、首页 | 返回 `/` |
| 岗位 | 点击展开菜单，包含“找岗位”“招聘日历”“备考中心”“央国企库” |
| 找岗位 | `/jobs` |
| 招聘日历 | `/calendar` |
| 备考中心 | `/preparation` |
| 央国企库 | `/companies` |
| 课程 | `/courses` |
| 主题模式 | 展开浅色、深色、跟随系统三个选项，并标识当前选择；本次验证了菜单，未遍历主题切换效果 |
| 招聘提醒图标 | 未登录时提示登录后设置招聘提醒，链接到 `/sign-in` |
| 登录 / 注册 | `/sign-in` |

### 2.2 统计与数据可信度说明

两页都展示累计收录、可筛职位、今日新增三个指标。调研时分别显示约 46 万+、40 万+、1000+ 条。岗位页另外说明数据来自可回溯来源的岗位库。

这些指标是平台总览，与当前条件的匹配结果数量不同。例如全国默认列表显示约 39 万+ 条，不能直接用总览数量代替筛选结果数。

### 2.3 页脚与隐私交互

- 品牌说明，以及“开始匹配”入口。首页指向本页搜索区 `#home-search`；岗位页观察到的链接同样指向本页 `#home-search`，是否能正确定位未验证。
- 微信小程序入口，控件提示悬浮查看二维码。
- 产品导航：岗位匹配、招聘公告、招聘窗口、岗位备考。
- 协议入口：数据与隐私 `/privacy`、隐私政策 `/privacy-policy`、用户协议 `/terms`。
- 公司名称、版权与备案链接。
- 首次访问出现数据分析同意提示，提供“同意产品分析”和“仅使用必要功能”；实测选择后提示消失。
- 页脚提供“分析与隐私设置”入口，其重新配置流程未展开验证。

## 3. 首页现有功能

### 3.1 页面角色与内容结构

按当前页面内容顺序，首页由以下部分组成：

| 模块 | 用户目的 | 主要内容 |
| --- | --- | --- |
| 品牌主张与筛选入口 | 快速找到适合自己的岗位 | 央国企求职定位、关键词与条件筛选、开始匹配 |
| 热门条件与招聘方向 | 减少输入成本，快速进入某类机会 | 热门城市、热门专业、招聘方向快捷入口 |
| 平台统计 | 了解岗位覆盖和更新规模 | 累计收录、可筛职位、今日新增 |
| 最新校招公告 | 发现近期招聘活动 | 企业、公告标题、招聘季、发布日期 |
| 抢投倒计时 | 发现临近截止的机会 | 已核验截止日期的岗位提示、招聘日历入口 |
| 精选推荐与判断依据 | 了解岗位条件，判断是否继续查看 | 推荐岗位摘要、当前岗位条件解释、详情入口 |
| 页脚 | 进入其他产品及支持页面 | 产品导航、微信入口、协议与公司信息 |

这些是功能模块，不要求新版沿用当前排列顺序。

### 3.2 岗位匹配表单

| 条件 | 现有选项与交互 |
| --- | --- |
| 关键词 | 搜索岗位或企业；文本输入；示例提示为岗位名称或企业名称 |
| 地区 | 默认全国；支持多个地区；弹窗按一级地区、二级城市选择，省份支持全省，直辖市支持全市；有重置、保存和关闭操作；选择后可清空地区 |
| 学历 | 默认不限；大专、本科、硕士、博士，可多选；选中后菜单出现清除已选入口 |
| 专业 | 默认不限；按学科门类 → 专业类 → 具体专业选择；支持选择某门类全类或某专业类整类；支持按专业名或代码搜索；有清除、完成、关闭操作 |
| 单位性质 | 默认不限；央国企、民营企业、外资企业、合资企业、事业单位、机关单位、社会组织、其他，可多选 |
| 招聘类型 | 单选；不限类型、校园招聘、社会招聘、实习岗位、兼职岗位、其他 |

专业目录首次打开时出现加载状态与取消加载入口；加载完成后出现选择弹窗。搜索结果区分专业类和具体专业，部分目录项带“硕博”标识。专业目录不是普通的自由文本输入框。

### 3.3 热门条件和已选条件

- 热门城市共展示 16 个：北京、上海、广州、深圳、杭州、成都、武汉、南京、西安、重庆、天津、苏州、青岛、郑州、长沙、合肥。
- 热门专业共展示 12 个：计算机类、电子信息类、电气类、机械类、自动化类、金融学类、会计学、法学类、土木类、材料类、通信工程、能源动力类。
- 热门城市用于快捷设置地区，地区允许多选；在岗位页实测同时选中北京和上海。
- 热门专业用于快捷设置专业条件；实测计算机类回填为“工学/计算机类”。
- 选择条件后显示“已选条件”标签，可移除单项，也可清空筛选。
- 选择条件本身不立即离开首页，点击“开始匹配”才进入岗位页。

实测提交“工程师 + 北京市 + 工学/计算机类”后进入带有对应查询参数的 `/jobs`，岗位页回显三项条件，并返回相应结果。

### 3.4 招聘方向快捷入口

这些入口直接进入带预设条件的岗位页，与手动填写筛选表单并列。

| 首页入口 | 现有链接参数 |
| --- | --- |
| 央国企岗位 | `companyNature=央国企` |
| 校园招聘 | `positionType=校招` |
| 军队文职 | `recruitmentTrack=military_civilian` |
| 公务员考试 | `recruitmentTrack=civil_service` |
| 社会招聘 | `recruitmentTrack=social_recruitment` |
| 更多方向：实习岗位 | `positionType=实习` |
| 更多方向：事业单位 | `recruitmentTrack=public_institution` |
| 更多方向：高校校招 | `recruitmentTrack=higher_education_campus` |
| 更多方向：医院 | `recruitmentTrack=hospital` |
| 更多方向：民企 500 强 | `recruitmentTrack=top_private_enterprise` |
| 更多方向：手机端使用 | 首页 `#footer-platforms`，指向平台入口区域 |

以上参数来自现有链接；未逐一验证每个招聘方向的返回数据。招聘方向、招聘类型和单位性质是不同概念，后续设计不宜直接混为同一个筛选维度。

### 3.5 最新发布的校招公告

- 调研时展示 6 张公告卡片。
- 每条包含企业名称、公告标题、招聘季标签（例如秋招）、发布日期和查看公告提示。
- 企业名称未确认时可显示“企业名称待核验”。
- 点击卡片进入 `/announcements/{id}`；“查看全部公告”进入 `/announcements`。
- 本模块展示招聘活动或公告，与下方的具体岗位推荐是两类内容。

### 3.6 抢投倒计时

- 用于汇总已核验截止日期的临近岗位。
- 页面明确说明：精选推荐中的预计日期不纳入此模块，投递前仍需核对来源状态。
- 调研时实际显示空状态：没有已核验截止日期的临近岗位。
- 提供“查看招聘日历”入口，进入 `/calendar`。
- 有数据时的卡片字段、倒计时形式与点击行为本次未验证，不能按模块名称推定已有实时倒计时组件。

### 3.7 精选推荐与判断依据联动

调研时展示 4 个推荐岗位。每个岗位包含：岗位名称、单位性质标签、单位名称、地点、学历、专业要求、截止日期及日期性质说明。

交互分为两个动作：

1. 点击岗位名称，进入该岗位的站内详情 `/jobs/{id}`。
2. 点击“查看依据”，留在首页，切换“判断依据”区域到所选岗位。

判断依据默认展示第一条推荐岗位，内容包括学历要求、专业要求、工作地点和投递截止信息。“查看岗位完整条件”链接跟随当前选中的岗位变化。实测切换到“信号处理算法工程师”后，条件内容和详情链接同步更新。

虽然页面使用“精准匹配”等文案，本次可确认的是岗位条件解释与联动展示，不能据此认定存在个人简历分析、匹配评分或真实个性化算法。

## 4. 岗位页 `/jobs` 现有功能

### 4.1 页面角色与默认状态

岗位页是检索、比较和进入详情的主工作区。顶部显示统计、首页面包屑、找岗位标题与核对原始公告的说明，其后为筛选区、结果区、分页和页脚。

默认状态：关键词为空，地区为全国，其他基础条件不限；更多筛选收起；按发布时间最新在前排列；每页 10 条。

页面说明，全国范围默认排除仅标注为海外的岗位，但保留地点为空、未知及同时包含境内与海外的岗位。因此“全国”不意味着所有条目地点都已确认。

### 4.2 基础筛选与提交

- 基础条件、热门城市、热门专业与首页基本一致，见第 3.2、3.3 节。
- 主按钮为“应用筛选”。从首页进入时，应能看到已带入的关键词与条件。
- 表单展示已选条件和条件项数；学历多选作为一个条件维度汇总显示。
- 支持移除某个条件；“清除条件”链接返回无筛选参数的 `/jobs`。
- 实测勾选学历后，表单与条件标签先变化，URL 不立即变化；点击应用筛选后才更新查询并检索。重新设计时需表达清楚“正在编辑的条件”与“已应用的结果”。
- 地区多选在页面说明中按满足任一地区匹配；其他复杂匹配规则未验证。

### 4.3 更多筛选

点击“更多筛选”展开附加条件。

| 条件 | 现有选项 | 状态 |
| --- | --- | --- |
| 岗位类别 | 不限、技术类、产品类、设计类、运营类、市场类、销售类、职能类、教育类 | 单选 |
| 毕业届别 | 不限、2024 至 2030 届 | 单选；年份是调研时选项 |
| 发布时间 | 全部时间、最近 7 天、最近 30 天 | 单选 |
| 仅看已完成独立核验的岗位 | 页面注明暂未开放，解释当前没有可筛选的已核验岗位 | 禁用，不应记为可用筛选 |

本次两页未观察到薪资筛选、工作经验筛选；工作经验是结果字段。不要因为其他招聘网站常见而补成现有功能。

### 4.4 匹配结果与字段

结果区展示匹配数量、当前排序方式、当前页与总页数。桌面主要采用可横向滚动的表格，默认每页展示 10 条。

| 字段 | 说明 |
| --- | --- |
| 岗位与单位 | 岗位标题和企业名称，共同构成站内详情入口 |
| 工作地点 | 可为省/市、多个地区，或待核验 |
| 学历 | 可列出多个允许学历，也可显示无要求 |
| 工作经验 | 例如经验不限、2 年、经验要求待核验 |
| 专业 | 允许专业或专业类的列表；内容可能较长 |
| 发布时间 | 岗位发布日期 |
| 截止日期 | 日期及其性质，例如预计截止日期 |
| 操作 | 查看原始公告入口，链接到外部招聘来源 |

截止日期、地点和工作经验的未知或待核验状态是重要信息，不能在重新设计时统一变成“已确认”。预计截止日期也不代表当前确认可投递。

### 4.5 排序

- 默认按发布时间降序，即最新在前。
- 可通过表头按岗位与单位、工作地点、学历、专业、发布时间、截止日期排序。
- 页面说明排序作用于全部结果，而不是仅对当前页排序。
- 链接中携带排序字段、方向和页码，切换排序回到第 1 页；实测截止日期排序产生 `sort=deadline&direction=asc&page=1`，保留已有筛选条件。
- 工作经验和操作列表头未观察到排序入口。

### 4.6 分页及登录限制

分页控件包括：

- 结果总数、本页条数。
- 每页条数菜单：10、20、50 条。
- 上一页、下一页；第 1 页的上一页不可用。
- 当前页 / 总页数。点击后切换成页码输入框，提示回车跳转。

**未登录限制已实测：** 点击默认列表的下一页，没有进入第 2 页，而是弹出“立即登录”对话框。弹窗介绍完整浏览岗位与公告、专属匹配推荐、收藏与上新订阅等权益，提供登录按钮、协议链接和关闭按钮。

因此，分页控件确实存在，但不能将未登录连续翻页描述为已可用。每页条数调整和任意页码提交是否也触发登录限制未逐一验证；登录后的分页结果也未验证。弹窗宣传的收藏、订阅及个性化功能不等于本次两页已验证的直接操作。

### 4.7 加载、零结果与近似匹配

| 状态 | 现有表现 |
| --- | --- |
| 首次加载岗位 | 显示岗位检索中的加载提示 |
| 更新筛选 | 结果区出现检索中状态；本次观察到新结果返回前短暂保留原列表 |
| 有精确结果 | 显示数量、结果表格、排序和分页 |
| 无精确结果 | 显示 0 条、条件组合没有精确匹配、暂无符合条件岗位及放宽条件提示 |
| 有可放宽的条件 | 指出限制结果的条件、保留其他条件后可获得的大致数量，提供移除该条件的入口 |
| 近似匹配 | 单独展示近似岗位，并说明具体放宽了哪项条件，不将其混充精确结果 |

实测使用不存在的关键词并保留“本科、硕士”条件：精确结果为 0；页面指出关键词限制了结果，提供移除关键词入口，并展示保留学历条件的近似岗位列表。近似列表也带有表格与分页。

未观察到网络失败状态，不能据此描述现有错误重试机制。

### 4.8 岗位详情与原始公告入口

列表上的两种入口用途不同：

- **站内详情**：进入 `/jobs/{id}`，阅读更完整的岗位条件。实测能在未登录状态打开一个样本岗位；跳转携带返回条件、排序、页码及滚动位置参数。
- **原始公告**：提供指向招聘来源网站的链接，用于核对原文。未执行外站申请或投递流程。

抽样详情页包含岗位基本信息、学历/地点/届别/经验等条件、介绍和任职要求、专业要求、单位摘要、原始公告入口，以及“返回岗位库”“查看该企业全部岗位”入口。其内容只作为占位页可能需要承接的信息参考，不纳入本次两页完整设计要求。

## 5. 关键页面关系与状态传递

| 起点 | 用户操作 | 终点或变化 |
| --- | --- | --- |
| 首页筛选区 | 设置条件并开始匹配 | `/jobs` 回显条件并展示结果 |
| 首页招聘方向 | 点击某类招聘入口 | 带单位性质、招聘类型或招聘方向的 `/jobs` |
| 首页推荐岗位 | 查看依据 | 留在首页，切换判断依据和详情链接 |
| 首页推荐岗位 | 点击岗位名称或完整条件 | 站内岗位详情 |
| 首页公告 | 点击公告或查看全部 | 公告详情或公告列表 |
| 首页倒计时 | 查看招聘日历 | 招聘日历 |
| 岗位页 | 编辑并应用筛选 | 更新查询、条件标签和结果 |
| 岗位页 | 点击可排序表头 | 保留筛选，调整排序并回到第一页 |
| 岗位页 | 未登录点击下一页 | 登录引导弹窗 |
| 岗位页零结果 | 放宽指定条件 | 进入放宽条件后的结果 |
| 岗位页条目 | 查看岗位 | 详情页携带返回上下文 |
| 岗位页条目 | 查看原始公告 | 原始招聘来源链接 |

已观察的 URL 状态包括关键词 `query`、地区 `city`、学历 `degree`、专业 `major`、单位性质 `companyNature`、招聘类型 `positionType`、招聘方向 `recruitmentTrack`、排序 `sort` / `direction`、页码 `page`。学历多选实测使用逗号分隔。详情页还观察到企业过滤 `companyId` 及返回状态 `returnTo` / `returnScroll`。

这些参数用于说明现有页面如何承接上下文；演示版不必照搬技术实现，但应让用户切换页面后仍能理解当前条件。

## 6. 首版交互演示的建议边界

> 本节是基于用户首版目标的范围建议，不是对现有网站功能的断言，也不是已经确认的新版设计方案。

### 6.1 建议真正可交互的主流程

| 功能 | 演示方式建议 |
| --- | --- |
| 首页与岗位页互相导航 | 使用真实前端路由 |
| 关键词和基础筛选 | 可以输入、选择、多选、清除，能看到条件变化 |
| 热门条件与招聘方向 | 更新条件或带预设条件进入岗位页 |
| 首页进入岗位页 | 传递并回显已选条件 |
| 推荐岗位判断依据 | 点击后切换对应岗位的说明 |
| 更多筛选 | 可展开/收起，选择后有状态反馈 |
| 应用筛选 | 使用本地模拟数据更新列表和数量 |
| 排序和分页 | 对模拟数据有效，演示比较与连续浏览体验 |
| 零结果与近似结果 | 准备至少一组可触发的演示场景，并提供恢复正常结果的操作 |
| 导航菜单、弹窗 | 能打开和关闭 |

对于分页，可在后续设计时选择保留现有登录引导，或让演示直接翻页以展示列表交互；后者属于演示简化，需要与现状区分。

### 6.2 可以占位或仅保留入口的功能

岗位详情、公告列表及详情、招聘日历、备考中心、央国企库、课程、登录注册、隐私协议等不在首版完整重写范围内，可以使用统一占位页面或弹窗。原始公告、招聘提醒、小程序入口等可保留展示，也可按演示需求不响应。

不要求真实账号、简历投递、收藏持久化、消息订阅、支付、后台岗位库、实时数据采集或智能推荐算法。模拟数据足以支撑两页交互。

### 6.3 演示数据需要覆盖的内容

- 岗位：标题、单位、单位性质、招聘类型、地点、学历、专业、经验、发布日期、截止日期及日期性质；更多筛选需要时补充岗位类别、毕业届别。
- 公告：标题、企业、招聘季和发布日期。
- 首页推荐：岗位摘要与可联动的判断依据。
- 特殊状态：地点待核验、经验要求待核验、预计截止日期、无临近截止岗位、无精确结果与近似推荐。
- 分页数据量应足以演示翻页，统计数字作为展示数据使用，不要求复刻真实岗位规模。

## 7. 后续设计时应保留的语义区别

1. 首页负责发现与进入，岗位页负责检索与比较。
2. 公告是一次招聘活动的信息，岗位是具体职位，两者不要混成同一种卡片数据。
3. 筛选条件用于缩小范围；“判断依据”解释岗位要求，不代表已验证的个人匹配评分。
4. 预计截止日期、已核验截止日期、来源状态待核验是不同状态。
5. “已按目录状态和截止日期初筛”不等于所有岗位已通过独立核验；现有独立核验筛选明确禁用。
6. 精确结果与放宽条件后的近似结果需要明确区分。
7. 页面存在的入口、登录后宣传的权益、实际验证成功的能力需要分开看待。
