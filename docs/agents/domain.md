# 领域文档

本仓库采用单上下文（single-context）布局。

## 探索代码前

- 阅读根目录的 `CONTEXT.md`，了解领域术语。
- 阅读 `docs/adr/` 中与当前工作相关的架构决策。
- 如果文件或目录不存在，直接继续，不报告缺失，也不提前建议创建。
- 领域术语或架构决策实际明确后，由 `domain-modeling` 按需创建文档。

## 文件布局

- `CONTEXT.md`：项目统一的领域上下文和术语。
- `docs/adr/`：项目架构决策记录。

## 使用领域术语

在任务标题、重构方案、问题假设等输出中，使用 `CONTEXT.md` 定义的术语，
避免使用术语表明确排除的同义词。

缺少所需概念时，先判断是否引入了项目不使用的概念；
确属术语缺口时，记录为后续 `domain-modeling` 的输入。

## 架构决策冲突

如果建议与现有 ADR 冲突，明确指出对应 ADR 和重新讨论的理由，
不得静默覆盖既有决策。
